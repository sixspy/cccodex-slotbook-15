# 代数拒确认册

| 项 | 值 |
|----|-----|
| 立册日 | 2026-11-21（当天禁止改口） |
| 症结 | 容量代数抬升后，挂旧代数的占位照样确认进正式册，账面容量与实占对不上；确认链路漏比代数 |
| 择定口径 | **甲路径：代数比对，整笔回滚** |

## 择定：甲路径

确认时比对**占位代数**（`holds.hold_gen`）与**档期现代数**（`slots.generation`）：

- 不一致 → 正式册**零增**，整笔回滚；拒写（记偏落审计）与回滚同败——拒确认路径上业务写尚未发生，记偏为唯一落账写，与"业务零写"天然同命运。
- 一致 → 照常入册，`bookings.snapshot_gen` 取档期现代数（此时与占位代数相等）。

## 明确排除：乙路径

不落漂移核销影子、不原子标旧代占位失效。两边不得混用。旧代占位被拒后维持`占位中`，留待自然过期，不做影子核销。

## 铁律

1. 跨代数占位禁止落正式。
2. 禁止只弹一句"容量已变更"：拒确认须落审计记偏（`confirm_reject_gen`），回执带双方代数。
3. 两人同时持旧代占位去确认须占档锁（`slot:<code>`），后到只记争用（`contention_log` 落账，业务零写）。
4. 五处同态：代数列（`slots.generation` / `holds.hold_gen` / `bookings.snapshot_gen`）、确认回执、正式册、对账灯、审计，同一笔确认在五处的口径一致。
5. 偏离本册口径的写入：拒写并记偏。

## 同态口径

| 场景 | 代数列 | 确认回执 | 正式册 | 对账灯 | 审计 |
|------|--------|----------|--------|--------|------|
| 同代确认 | 三者相等 | 200 + `snapshot_gen` | +1 行已确认 | ok 且无漂移 | `booking_confirm` |
| 跨代拒确认 | 不动 | 409 + 双方代数 | 零增 | ok 且不翻红 | `confirm_reject_gen`（记偏） |
| 后到争用 | 不动 | 409 争用 | 零增 | 不动 | 只记 `contention_log` |

对账灯漂移判据：`bookings.snapshot_gen ≠ 来源占位 holds.hold_gen`（按 `hold_id` 互证）；`stale_holds`（占位中但代数已旧）仅作展示，不翻红——甲路径下旧代占位在确认口被拦，不自动作废。

## 实施范围

确认服务（比对+拒写）、档期服务（调容抬代数）、占位服务（占位打代数，含候补晋升这条占位写入）、对账服务（漂移判据）。库层加 `holds.hold_gen` 列并对存量库做迁移。
